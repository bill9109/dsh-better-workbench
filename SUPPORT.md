# Support

## Start here

- Read [README.md](README.md) for installation, usage, lifecycle, and troubleshooting.
- Read the [application-authoring Skill](docs/application-authoring/SKILL.md) when developing a Workbench application.
- Search existing [issues](https://github.com/bill9109/dsh-workbench/issues) and [pull requests](https://github.com/bill9109/dsh-workbench/pulls) before opening a duplicate.

## Where to ask

- Reproducible defect: open a bug report.
- Installation, application registration, or usage question: open a question.
- Focused product or protocol improvement: open a feature request.
- Security concern: follow [SECURITY.md](SECURITY.md) and report it privately.
- Code contribution: read [CONTRIBUTING.md](CONTRIBUTING.md) before opening a pull request.

## Information to include

Provide the DSH snapshot and profile, Workbench and application versions, browser and operating-system versions, installed Workbench application IDs, the active presentation, minimal reproduction steps, expected behavior, and sanitized console output. Remove API keys, authorization headers, complete prompts or conversations, and unrelated workspace data.
